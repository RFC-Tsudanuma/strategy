# 戦略を書く上でのルール

- 関数とメソッドに対しては、**必ず型注釈を書く**。
- 現実世界に適用するアクションは`real_action`以下に実装する。

## 座標系
- フィールドの座標系
  - フィールドの中心が(0,0)
  - フィールドの右向きが +x
  - フィールドの上向きが +y
  - 右手系
- ロボットの座標系
  - ロボットの前方が +x
  - ロボットの左側が +y
  - 右手系

## アクションの書き方

- アクションは1種類しかない。以前存在した仮想アクションは使わない実装に変わった。
- アクションでは、事前条件を満たさないなど、次の遷移に移れない場合(planのやり直しが必要な場合)はFalseを返す。事前条件を満たしている場合は、引数として受け取った状態をそのまま返す。
  - 実装例は既存のreal_action/actions.py/approach_ball()等を参考にする。
- アクションに入ったが、事後条件を既に満たしている場合、そのアクションでは行動せずにそのままstateを返すようにする。ここで重要なのは、**False**を返さないこと。この状況でFalseを返してしまうと、この後に実行すべきアクションが実行されなくなってしまう。
  - 例： approach_ball()に入ったが、既に事後条件`BALL_POSITION.NEAR`を満たしている場合。この場合は、approach_ball()では何も行動せず（= 何もコマンドを送信せず）すぐに`return s`をする。
